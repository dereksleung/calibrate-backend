Implementation plan · dashboard

Turn nutrition fixtures into a live weekly view.

The dashboard will fetch one authenticated Sunday–Saturday range, total each day’s food entries, and render real calories, fats, protein, and carbohydrates without changing the log page’s existing day endpoint.

Chosen API boundary

GET /api/v1/daylogs/week/:weekStart

The route accepts an ISO Sunday. It returns an inclusive Sunday–Saturday response containing seven date slots. A missing log is represented as dayLog: null, never as a missing day.

How the data travels

Why this approach

Leave daily logs alone

The logs page continues to consume GET /daylogs/:date unchanged.

  • No client migration
  • No response-shape breakage

Make absence explicit

Seven slots prevent bars from disappearing when no log exists for a day.

  • Empty days are zero
  • Weekdays stay stable

Fetch once, derive four cards

The dashboard gets one query, then calculates all four metrics locally.

  • Consistent chart dates
  • No duplicate requests

Implementation sequence

Task 1

Contract + application query

Medium · foundation

Define the Sunday validator, exact seven-slot response, and user-scoped range read. Unit-test invalid dates, sequence guarantees, empty results, and error propagation.
Task 2

Repository + HTTP endpoint

Large · protected read

Use one bounded day-log query and one batched food-entry query, reconstitute aggregates, fill empty slots at the controller boundary, and test authentication and ownership.
Task 3

API client + cache refresh

Medium · transport

Add the typed weekly query and distinct React Query key. After food saves, invalidate both the individual day and week-query namespace.
Task 4

Dashboard model + cards

Large · user-facing

Fetch one week at the dashboard boundary, derive calories/fats/protein/carbs models, remove fixtures, preserve accessible text alternatives, and render loading and error states.
Task 5

Regression checkpoint

Small · proof

Run contracts, backend, API-client, and web checks; confirm a saved food entry refreshes all appropriate dashboard charts.

Scope boundary

Live means food-intake totals are live. Personalized nutrition goals remain a follow-up because no goal persistence or API exists today.

Key risk

Timezone drift can show the wrong week. The browser therefore computes and submits a local Sunday; the backend treats it only as a calendar range.

Proof of completion

  • All four dashboard cards derive totals from the week response; no dashboard fixture values remain.
  • The endpoint returns only the authenticated user's logs and exactly seven ordered date slots.
  • Missing logs and empty meals render as zero while preserving chart and text-table accessibility.
  • Saving a food entry invalidates the cached week so a mounted dashboard refreshes.
  • Focused contracts, backend, API-client, and web test/typecheck commands pass.
